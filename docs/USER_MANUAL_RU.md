# ChannelOS — руководство пользователя

> Версия руководства: ChannelOS v0.3.0, актуальный main на момент подготовки документации.
>
> Это руководство для конечного пользователя Web-панели. Оно не объясняет Docker, Nginx, PostgreSQL, Redis, SSH и развёртывание сервера. ChannelOS уже должен быть установлен и доступен по URL.

## О документе и границы проверки

Руководство составлено по фактически реализованному frontend и backend ChannelOS, а не только по README или ROADMAP. Названия кнопок, статусы, маршруты, доступные действия и ограничения ниже соответствуют текущему русскому интерфейсу v0.3.0.

В AUDIT.md для v0.3.0 уже зафиксирован production smoke-test основных экранов: Обзор, Каналы, Аккаунты, Наборы каналов, Посты, Content Studio, Календарь, Задачи, Расходы и Настройки. При подготовке этого руководства реальные Telegram-отправки и платные AI-вызовы повторно не выполнялись: их поведение сверено по текущему backend и существующей документации. Фальшивые скриншоты в руководство не добавлялись.

> **Важно:** если ROADMAP описывает функцию шире, чем текущая панель, это руководство описывает только то, что реально доступно пользователю сейчас.

## Что такое ChannelOS

ChannelOS — рабочая Web-панель для управления сетью Telegram-каналов. В одном месте можно подключить Telegram-аккаунты, импортировать каналы, объединить их в наборы, создавать и редактировать контент, использовать AI, согласовывать посты, планировать время, публиковать, разбирать ошибки и контролировать расходы.

Главная идея продукта:

**один Content Item → один Distribution Batch → отдельная Publication для каждого канала.**

Это важно понять до начала работы. Если вы создали один пост и выбрали набор из десяти каналов, ChannelOS не обязан десять раз генерировать текст. Сначала существует один контент, затем система создаёт отдельную публикацию для каждого выбранного канала. Поэтому успех или ошибка одного канала не смешивается с остальными.

Пример:

- создан один пост «Как считать CPA»;
- выбран набор Talos Network из 10 каналов;
- AI сгенерировал текст один раз;
- ChannelOS подготовил 10 отдельных публикаций;
- 8 успешно отправились;
- 2 получили ошибку;
- повторить можно только эти 2.

> **Важно:** не создавайте вручную копии одного и того же поста только потому, что он должен уйти в несколько каналов. Для этого существует Набор каналов.

## Основные понятия

| Термин | Простое объяснение |
| --- | --- |
| **Рабочее пространство (Workspace)** | Общая область команды: каналы, посты, настройки, бюджет, участники. |
| **Telegram-аккаунт** | Реальный Telegram-пользователь, через сессию которого ChannelOS видит администрируемые каналы и публикует. |
| **Канал** | Импортированный Telegram-канал, которым подключённый аккаунт может управлять или управлял ранее. |
| **Набор каналов (Channel Set)** | Группа каналов — например, Talos Network из 10 каналов. Выбирается как цель одного поста. |
| **Пост / Content Item** | Сам контент: заголовок, текст, изображение, цель, тон, статус и история версий. |
| **Публикация (Publication)** | Отдельная попытка доставить этот пост в один конкретный канал. |
| **Рассылка (Distribution Batch)** | Группа публикаций одного Content Item во все каналы выбранного набора. |
| **Расписание (Schedule)** | Правило, определяющее допустимые дни и временные окна для публикаций. |
| **Задача (Job)** | Фоновая операция: AI-генерация, публикация, импорт каналов, загрузка источника и т. п. |
| **Подтверждение (Approval)** | Ручная проверка перед публикацией. |
| **Серия (Series)** | Последовательность связанных постов с планом тем и нумерацией. |
| **Источник (Source)** | RSS, страница, ручная ссылка или Telegram-канал, из которых ChannelOS получает материалы. |
| **Идея (Idea)** | Найденный материал-кандидат. Идея ещё не является постом. |
| **База знаний (Knowledge)** | Факты, правила, контакты и примеры, которыми AI может пользоваться при генерации. |
| **Тон и стиль (Tone of Voice)** | Профиль языка, обращения, формальности, эмодзи, длины, CTA и словаря. |
| **Автопилот** | Автоматическое планирование AI-контента с выбранной степенью ручного контроля. |

## Первый запуск: от пустой панели до первого поста

Ниже — безопасный путь для человека, который впервые открыл ChannelOS.

### Шаг 1. Войдите в ChannelOS

Откройте адрес панели.

Если аккаунт уже существует:

1. введите **Эл. почта**;
2. введите **Пароль**;
3. нажмите **Войти**.

Если это новый аккаунт:

1. нажмите **Нет рабочего пространства? Создайте его**;
2. заполните **Имя и фамилия**;
3. укажите email;
4. задайте пароль не короче 8 символов;
5. укажите **Название рабочего пространства**;
6. нажмите **Создать аккаунт**.

Переключатель **EN / RU** доступен прямо на экране входа.

### Шаг 2. Подключите Telegram

Путь: **Дистрибуция → Аккаунты → Добавить аккаунт**.

1. Введите номер в международном формате, например **+79991234567**.
2. Отправьте код.
3. Введите код Telegram.
4. Если Telegram запросил двухэтапную аутентификацию, введите пароль 2FA.
5. Дождитесь статуса **Подключён**.

После успешного входа ChannelOS автоматически создаёт задачу импорта каналов.

> **Осторожно:** никому не передавайте код Telegram и пароль 2FA. ChannelOS использует их только для текущего шага авторизации; сам код и пароль 2FA не сохраняются.

### Шаг 3. Проверьте каналы

Путь: **Дистрибуция → Каналы**.

Вы увидите импортированные каналы. Для первого теста выберите каналы со статусом **Работает**.

Если каналов нет:

1. вернитесь в **Аккаунты**;
2. нажмите **Обновить каналы**;
3. откройте **Автоматизация → Задачи**;
4. найдите задачу **Импорт каналов**;
5. если она завершилась ошибкой, откройте подробности.

### Шаг 4. Создайте Набор каналов

Путь: **Дистрибуция → Наборы каналов → Новый набор каналов**.

Пример:

- название: **Talos Network**;
- описание: **Основные каналы**;
- режим: **Одинаковый текст**;
- выберите нужные каналы.

Сохраните набор.

### Шаг 5. Создайте пост

Путь: **Контент → Посты**.

Для ручного текста нажмите **Создать пост**.

Для AI нажмите **Сгенерировать с AI**. Введите, например:

**Напиши короткий обучающий пост о том, как считать CPA перед тестом рекламной кампании. Русский язык, без рекламных клише.**

При желании сразу выберите Talos Network.

### Шаг 6. Проверьте текст в Content Studio

Открывшийся Content Studio — основное место работы с постом.

Проверьте:

- заголовок;
- основной текст;
- набор каналов;
- профиль тона;
- форматирование;
- Telegram-превью;
- изображение;
- предупреждения о дубликатах и рисках.

После ручных правок нажмите **Сохранить изменения**.

### Шаг 7. При необходимости используйте AI-правки

В текущей версии доступны:

- Переписать;
- Сократить;
- Расширить;
- Изменить тон;
- Улучшить;
- Сгенерировать заголовок;
- Перегенерировать фрагмент;
- Сгенерировать призыв;
- Убрать AI-клише.

Каждый AI-вызов расходует бюджет и появляется в истории затрат поста.

### Шаг 8. Отправьте на подтверждение

Нажмите **Отправить на подтверждение**.

Пост перейдёт в **Ожидает подтверждения**.

### Шаг 9. Подтвердите

Путь: **Контент → Подтверждение**.

Откройте пост и нажмите **Подтвердить**. Если текст нужно вернуть, нажмите **Отклонить**.

### Шаг 10. Выберите способ публикации

Для подтверждённого поста доступны:

- **Опубликовать сейчас**;
- выбрать точную дату и время и **Запланировать**;
- выбрать расписание и использовать **Ближайший свободный слот**.

### Шаг 11. Проверьте публикации по каналам

После подготовки/отправки в Content Studio появится блок рассылки.

Для набора из 10 каналов результат может быть:

- 8 успешно;
- 2 ошибки.

Нажмите **Повторить неудачные публикации** — успешные 8 повторно не уйдут.

Если система пишет **Доставка не подтверждена**, сначала вручную откройте Telegram и проверьте канал. Затем отметьте публикацию как доставленную или не доставленную.

### Шаг 12. Посмотрите расходы и состояние

Откройте:

- **Аналитика → Расходы**;
- **Автоматизация → Задачи**;
- **Система → Уведомления**;
- **Система → Журнал аудита**.

На этом базовый цикл завершён.

## Вход, регистрация и язык

### Вход

Экран входа содержит email, пароль и кнопку **Войти**. Парольное поле требует минимум 8 символов на уровне формы.

Типичные ошибки:

- **Неверный email или пароль** — проверьте данные;
- **Слишком много попыток входа** — дождитесь окончания ограничения;
- **Сессия истекла** — войдите снова;
- **Аккаунт отключён** — нужен администратор системы.

### Регистрация

Регистрация создаёт не только пользователя, но и первое рабочее пространство. Обязательны:

- имя;
- email;
- пароль;
- название пространства.

### Выход

Откройте меню пользователя в верхней части интерфейса и нажмите **Выйти**.

### Язык интерфейса

Доступны русский и английский.

Изменить язык можно:

- переключателем EN/RU на экране входа;
- через меню пользователя в шапке;
- **Настройки → Общие → Язык интерфейса**.

Сохранённый язык привязан к аккаунту и применяется на других устройствах. Явный локальный выбор также хранится в браузере. Если пользователь ещё ничего не выбирал, ChannelOS может взять язык браузера; для русского локали ru/ru-RU выбирается русский, иначе английский.

> **Важно:** смена языка интерфейса не переводит тексты постов, названия каналов, AI-промпты и Tone Profile.

## Обзор

Путь: **Обзор**.

Страница автоматически обновляет основные данные примерно раз в 30 секунд.

### Верхние показатели

**Каналы** — количество управляемых каналов в пространстве.

**Аккаунты** — количество подключённых Telegram-аккаунтов.

**Постов сегодня** — контент за текущий день по данным Dashboard.

**Запланировано** — сколько постов сейчас ожидают своего времени.

**Ждут подтверждения** — сколько постов находится в очереди Approval.

**Ошибки (7 дн.)** — сумма недавних ошибок публикаций и фоновых задач. Если число растёт, первым делом откройте **Последние ошибки** и **Задачи**.

### AI и бюджет

**AI сегодня** — стоимость AI-запросов за текущий день.

**Месяц / бюджет** — потрачено в текущем месяце и месячный лимит.

**Прогноз на месяц** — экстраполяция текущего темпа расходов до конца месяца. Это оценка, а не счёт к оплате.

### Ближайшие публикации

Показывает следующие запланированные посты. В строке видны:

- время;
- набор каналов;
- доставлено X/Y;
- просмотры;
- статус.

Нажатие открывает пост.

### Недавно опубликованные

Недавние публикации с теми же ключевыми показателями.

### Последние ошибки

Показывает проблемный пост, канал и понятную причину, если код ошибки известен. Нажмите строку, чтобы открыть Content Studio и рассылку.

### Состояние системы

Пользователю показывается доступность:

- PostgreSQL;
- Redis;
- хранилища медиа S3;
- воркера;
- планировщика.

Также показываются текстовый AI-провайдер, статус провайдера изображений и состояния Telegram-аккаунтов.

Что считать проблемой:

- **Воркер — Недоступно**: фоновые задачи не исполняются;
- **Планировщик — Недоступно**: запланированные публикации и периодические операции не запускаются вовремя;
- **Redis — Недоступно**: очередь/координация и Telegram login flow могут не работать;
- **S3 — Недоступно**: медиа может не загружаться;
- Telegram **Нужен повторный вход**: переподключите аккаунт.

### Просмотры за 7 дней

Если метрики уже получены, Dashboard показывает график просмотров последних семи дней публикаций. Если данных нет, дождитесь первого обновления метрик после публикаций.

### Лучшие посты

Список наиболее сильных постов по доступным метрикам. Нажатие открывает пост.

## Telegram-аккаунты

Путь: **Дистрибуция → Аккаунты**.

### Что такое Telegram-аккаунт

ChannelOS публикует не «от имени сайта», а через сохранённую Telegram-сессию подключённого пользователя. Этот пользователь должен иметь нужные права в каналах.

В карточке аккаунта видны:

- имя/username;
- замаскированный телефон;
- статус;
- количество каналов;
- FloodWait до определённого времени, если есть;
- последняя ошибка.

### Как добавить аккаунт

Нажмите **Добавить аккаунт**.

#### 1. Номер телефона

Используйте международный формат с плюсом.

Правильно: **+79991234567**.

Если формат неверен, ChannelOS покажет ошибку.

#### 2. Код Telegram

После отправки номера Telegram выдаёт код. Введите его в ChannelOS.

Login flow живёт ограниченное время — около 10 минут. Если он истёк, начните заново и получите новый код.

#### 3. Пароль 2FA

Если у аккаунта включена двухэтапная аутентификация, появится дополнительный шаг.

Для кода и 2FA предусмотрено ограниченное число попыток. Не перебирайте значения.

#### 4. Успешное подключение

После завершения:

- финальная Telegram-сессия сохраняется в зашифрованном виде;
- временные данные входа очищаются;
- автоматически создаётся задача импорта каналов.

### Статусы аккаунта

**Подключён (CONNECTED)**  
Сессия действует. Это нормальное рабочее состояние.

**Отключён (DISCONNECTED)**  
Аккаунт отключён внутри ChannelOS. Не путайте с удалением Telegram-профиля.

**Нужен повторный вход (AUTH_REQUIRED)**  
Telegram больше не принимает сохранённую сессию. В текущем UI отдельной кнопки «Reconnect» нет. Нажмите **Добавить аккаунт** и снова пройдите вход тем же Telegram-пользователем. Backend распознаёт уже существующего пользователя в этом рабочем пространстве и обновляет его запись вместо создания дубля.

**Нужен пароль 2FA (TWO_FA_REQUIRED)**  
Состояние авторизации требует пароль двухэтапной защиты.

**Ограничение Telegram (FLOOD_WAIT)**  
Telegram попросил временно прекратить запросы. Обычно нужно просто дождаться указанного времени.

**Ошибка (ERROR)**  
Посмотрите текст последней ошибки и раздел **Задачи**.

**Отключён (DISABLED)**  
Запись выключена системой/конфигурацией. Для восстановления может потребоваться администратор.

### Доступные действия

**Обновить каналы**  
Запускает фоновую задачу повторного чтения администрируемых каналов.

**Отключить**  
Меняет состояние аккаунта в ChannelOS на DISCONNECTED. Это не удаляет ваш Telegram-аккаунт.

**Удалить**  
Удаляет подключение из ChannelOS. Это также не удаляет сам Telegram-профиль в Telegram, но может повлиять на связанные данные и возможность публиковать из панели.

> **Осторожно:** не удаляйте аккаунт только из-за FloodWait. FloodWait — временное ограничение, а не признак «сломавшейся» учётной записи.

### Обновление списка каналов

При Refresh ChannelOS:

- загружает каналы, которые аккаунт администрирует;
- обновляет название, username, права и число подписчиков;
- помечает канал **Работает**, если публикация разрешена;
- помечает **Нет прав на публикацию**, если прав нет;
- канал, который больше не администрируется, оставляет в истории, но помечает **Недоступен**.

## Каналы

Путь: **Дистрибуция → Каналы**.

### Что такое управляемый канал

Это Telegram-канал, обнаруженный через подключённый аккаунт и сохранённый в рабочем пространстве.

Карточка показывает:

- название;
- username или признак приватного канала;
- здоровье;
- подписчиков;
- Telegram-аккаунт и его статус;
- последнюю публикацию;
- следующую публикацию;
- число постов за 30 дней;
- переключатель Autopilot для канала.

### Здоровье канала

**Работает (HEALTHY)**  
Есть доступ и право публикации.

**Нет прав на публикацию (NO_POST_PERMISSION)**  
Подключённый аккаунт видит канал, но не может туда писать. Исправьте права в Telegram, затем обновите каналы.

**Аккаунт недоступен (ACCOUNT_OFFLINE)**  
Проблема с аккаунтом, через который подключён канал.

**Ограничение Telegram (FLOOD_WAIT)**  
Публикации временно ограничены Telegram.

**Недоступен (UNAVAILABLE)**  
Например, аккаунт больше не администрирует канал или Telegram-объект недоступен.

### Настройки канала

Откройте настройки карточки. В текущей версии доступны:

**Профиль тона**  
Переопределяет workspace-уровень для контента этого канала, если серия или явный выбор в Content Studio не имеют более высокого приоритета.

**Часовой пояс**  
Локальная настройка канала.

**CTA overrides**  
Для системных CTA-ключей можно указать собственные значения канала. Это особенно полезно в режиме набора **CTA для каждого канала** / **Контакт для каждого канала**.

**Autopilot**  
У канала есть отдельный флаг включения автоматизации. При этом основная конфигурация Autopilot задаётся на отдельной странице и выбирает целевой Набор каналов.

В текущем редакторе канала нет отдельных полей для привязки расписания, лимита бюджета или смены Telegram-аккаунта. Не ищите их здесь.

## Наборы каналов

Путь: **Дистрибуция → Наборы каналов**.

Это одна из центральных функций ChannelOS.

### Зачем нужен набор

Представьте 10 каналов. Вместо десяти отдельных постов создайте:

**Talos Network**
- Channel A
- Channel B
- …
- Channel J

Теперь один Content Item может породить 10 Publications.

### Создание

Нажмите **Новый набор каналов**.

Заполните:

- название;
- описание;
- режим распространения;
- отметьте каналы.

### Режимы текущего UI

**Одинаковый текст (EXACT)**  
Текст поста одинаков для всех каналов. Если у Content Item есть CTA key, используется workspace-значение CTA.

**CTA для каждого канала (CTA_PER_CHANNEL)**  
Основной текст общий. CTA может подставляться из override конкретного канала; если override нет, используется workspace default.

**Контакт для каждого канала (CONTACT_PER_CHANNEL)**  
В текущем backend обрабатывается тем же механизмом резолвинга CTA/контакта: основной текст не генерируется заново, а локальное значение подставляется для канала.

**ADAPTED**  
Такой backend enum существует, но в редакторе Channel Set v0.3.0 пользователю он не предлагается. Не рассчитывайте на него как на доступную функцию панели.

### Что видно в карточке/деталях

- число каналов;
- сколько из них готовы;
- режим;
- общая аудитория;
- просмотры;
- публикации;
- список каналов и их здоровье;
- недавний контент.

### Пример 8 success / 2 failed

Система создаёт десять независимых Publication.

Если восемь SUCCESS, а две FAILED:

- Content Item становится **Опубликован частично**;
- в блоке рассылки видно, какие каналы не прошли;
- кнопка **Повторить неудачные публикации** ставит в очередь только FAILED.

Успешные восемь не создаются заново и не отправляются повторно.

> **Осторожно:** не делайте новый пост и не жмите Publish Now заново «для надёжности». Используйте Retry Failed.

## Посты и статусы

Путь: **Контент → Посты**.

### Список

Можно:

- искать по заголовку, тексту и теме;
- фильтровать по основным статусам;
- открывать Content Studio;
- создавать ручной черновик;
- запускать AI-генерацию;
- подгружать следующие страницы списка.

Карточка показывает название/тему, статус, фрагмент, Набор каналов и AI-стоимость.

### Полный жизненный цикл статусов

**Идея (IDEA)**  
Служебное раннее состояние. В обычном списке может встречаться редко: генерация быстро переводит объект дальше.

**Черновик (DRAFT)**  
Редактируемый пост. Его можно сохранить и отправить на подтверждение.

**Генерируется (GENERATING)**  
AI-задача ещё выполняется. Не запускайте несколько генераций одного и того же объекта.

**Ожидает подтверждения (PENDING_APPROVAL)**  
Пост находится в очереди Approval.

**Подтверждён (APPROVED)**  
Можно поставить время, выбрать ближайший слот или опубликовать сейчас.

**Запланирован (SCHEDULED)**  
Есть конкретное scheduled_at. Можно перенести или снять с расписания.

**Публикуется (PUBLISHING)**  
Созданы/запущены отдельные Telegram-публикации.

**Опубликован (PUBLISHED)**  
Все публикации завершились успешно.

**Опубликован частично (PARTIALLY_PUBLISHED)**  
Хотя бы одна публикация успешна, но есть и FAILED.

**Ошибка (FAILED)**  
Генерация или вся рассылка завершилась неудачей.

**Отклонён (REJECTED)**  
Согласующий вернул пост. Его можно снова доработать.

**В архиве (ARCHIVED)**  
Пост сохранён для истории, но больше не участвует в обычном рабочем цикле.

### Что не видно отдельным фильтром

В списке текущий dropdown статусов показывает не каждый backend enum отдельной опцией. Например, PARTIALLY_PUBLISHED и REJECTED могут существовать, хотя не имеют собственной кнопки фильтра в текущем наборе быстрых фильтров. Найти их можно через общий список/поиск и связанные экраны.

## Content Studio

Это самый важный редактор ChannelOS. Он открывается из списка постов, Approval, календаря и некоторых других переходов.

### Когда текст можно редактировать

Редактор включён для рабочих состояний вроде:

- Черновик;
- Идея;
- Отклонён;
- Ожидает подтверждения;
- Подтверждён;
- Запланирован.

При публикации или после завершения доставки редактирование ограничивается.

### Заголовок

Поле заголовка используется:

- в списке;
- уведомлениях;
- версиях;
- аналитике;
- карточках календаря.

### Набор каналов

Выберите цель публикации. Для уже запланированного поста селектор блокируется, чтобы не менять рассылку под готовым планом незаметно.

Если попытаться планировать без цели, будет ошибка **Сначала выберите набор каналов**.

Если набор пуст, будет ошибка **В наборе нет каналов**.

### Тон

Можно явно выбрать Tone Profile.

Content Studio показывает, откуда фактически взялся тон. Приоритет:

1. явный выбор в Content Studio;
2. серия;
3. канал;
4. workspace default;
5. отсутствие профиля.

### Редактор текста

Поддерживается Telegram-совместимое форматирование:

- жирный;
- курсив;
- подчёркивание;
- зачёркивание;
- inline code;
- маркированный список;
- нумерованный список;
- цитата;
- блок кода.

Интерфейс показывает длину и не позволяет сохранить контент, выходящий за допустимый предел.

### Сохранение

После ручных правок нажмите **Сохранить изменения**.

Пока есть несохранённые изменения:

- часть действий блокируется;
- при уходе со страницы появляется предупреждение;
- AI-трансформацию лучше не запускать, пока не сохранён текущий вариант.

### AI Generate

Первичная генерация запускается из страницы Посты через **Сгенерировать с AI**.

Она:

1. создаёт Content Item в состоянии GENERATING;
2. ставит AI Job;
3. вызывает текстовый провайдер;
4. записывает результат;
5. создаёт первую AI-версию;
6. переводит объект в DRAFT.

AI не вызывается заново при обычном fan-out по Channel Set.

### AI-трансформации

#### Переписать

Переформулирует текст. Используйте, когда содержание подходит, а подача — нет.

#### Сократить

Сжимает текст, сохраняя смысл.

#### Расширить

Добавляет подробности и связность.

#### Изменить тон

Переписывает под выбранный Tone Profile/инструкцию.

#### Улучшить

Общая редакторская правка.

#### Сгенерировать заголовок

Меняет/предлагает заголовок на основе контента.

#### Перегенерировать фрагмент

Работает только с выделенным фрагментом. Если ничего не выделено, ChannelOS покажет **Сначала выделите фрагмент текста**.

#### Сгенерировать призыв

Генерирует CTA.

#### Убрать AI-клише

Пытается убрать характерные шаблонные формулировки.

### Стоимость AI-действий

Каждое AI-действие является отдельным запросом и может тратить бюджет.

Для поста видно:

- операцию;
- число запросов;
- неудачные запросы;
- входные токены;
- выходные токены;
- стоимость;
- итог текста;
- итог изображения;
- общий итог.

### Медиа

Можно:

- выбрать изображение из Галереи;
- отвязать его;
- при доступном провайдере сгенерировать AI-изображение.

В production v0.3.0 реальный Timeweb image provider помечен как недоступный, поэтому генерация изображения отключена. Загрузка и использование своих изображений работают.

### Telegram Preview

Можно переключать представление и смотреть, как контент будет выглядеть в Telegram. Это предпросмотр, а не реальная отправка.

### Предупреждение о дубликате

Для похожего на недавний контент вычисляется duplicate score. В интерфейсе показывается предупреждение при заметной похожести. Autopilot имеет более строгий блокирующий порог.

### Risk flags / требуется проверка

Если AI отметил пост как требующий ручного review, это предупреждение сохраняется. Даже полный Autopilot в таких случаях отправляет пост в Approval вместо автоматического продвижения.

## История версий

Content Studio хранит ContentRevision.

В истории видны:

- v1, v2, v3…;
- действие;
- автор или Autopilot;
- время;
- AI/ручная версия;
- цена AI-действия, если она была;
- сравнение с текущим содержимым.

### Посмотреть старую версию

Нажмите действие просмотра у нужной версии. Можно увидеть её текст и diff.

### Restore

Восстановление не стирает историю.

ChannelOS:

1. берёт заголовок и Telegram HTML старой ревизии;
2. делает их текущим содержимым;
3. создаёт новую ревизию с действием Restore;
4. если пост был уже **Подтверждён**, возвращает его в **Ожидает подтверждения**.

Это безопаснее, чем «перемотка истории»: видно и старую версию, и факт восстановления.

## Подтверждение

Путь: **Контент → Подтверждение**.

### Как устроена очередь

В текущем v0.3.0 это не отдельный тип карточки с независимым редактором. Страница фактически показывает список постов, отфильтрованный по **Ожидает подтверждения**, и открывает тот же Content Studio.

Это удобно: проверяющий видит ровно тот же текст, изображение, warnings, цель, версии и расходы.

### Рекомендуемый режим новичку

**AI → ручная проверка → Подтвердить → расписание/публикация.**

Не начинайте с полного Autopilot на всех каналах.

### Действия

**Подтвердить**  
Переводит PENDING_APPROVAL → APPROVED.

**Отклонить**  
Переводит в REJECTED. После правок редактор может снова отправить пост на подтверждение.

**Изменить**  
Поля Content Studio доступны, пока статус допускает редактирование. После ручной правки сохраните изменения.

AI-трансформации также доступны в редактируемых состояниях и создают новые версии.

### Кто может подтвердить

Минимальная роль — **Согласующий (APPROVER)**. Более высокие по рангу роли также проходят проверку. Редактор сам по себе не получает это право только потому, что умеет менять текст.

## Публикация и рассылка

### Подготовка batch

Когда подтверждённый пост получает конкретное время или Publish Now, ChannelOS:

1. проверяет, что выбран Channel Set;
2. проверяет, что в нём есть каналы;
3. создаёт Distribution Batch;
4. создаёт Publication на каждый канал;
5. применяет режим Channel Set и CTA;
6. сохраняет отдельный idempotency key для публикации.

### Publish Now

Кнопка не «стреляет напрямую из браузера». Она ставит пост на немедленное время и дальше планировщик/воркер проводят обычный безопасный workflow.

### Статусы отдельной Publication

**Ожидает (PENDING)** — ещё не взята воркером.

**Подготовка (CLAIMED)** — воркер атомарно забрал работу.

**Отправляется (SENDING)** — запрос к Telegram уже начался.

**Опубликовано (SUCCESS)** — Telegram подтвердил отправку.

**Ошибка (FAILED)** — есть окончательная ошибка либо исчерпаны разрешённые попытки.

### Почему идемпотентность важна

Если задача публикации повторно запустится для уже SUCCESS-строки, она не отправит сообщение второй раз. Воркеры работают с отдельными Publication, а не с одним общим «отправить всё».

### Retry Failed

Повторно ставятся в очередь только FAILED.

SUCCESS не меняются.

Публикации с неопределённой доставкой также не подхватываются Retry Failed автоматически.

### Доставка не подтверждена

Самый важный специальный случай.

Если процесс уже начал отправку, но связь оборвалась в момент, когда невозможно понять, принял Telegram сообщение или нет, ChannelOS оставляет публикацию в состоянии SENDING/CLAIMED с ошибкой **DELIVERY_UNKNOWN**.

Что делать:

1. вручную откройте соответствующий Telegram-канал;
2. найдите сообщение;
3. если оно есть — нажмите **Подтвердить публикацию**;
4. если его нет — нажмите **Подтвердить, что не доставлено**;
5. после отметки Failed можно безопасно повторить.

> **Осторожно:** не нажимайте Retry до ручной проверки DELIVERY_UNKNOWN. Это специально заблокировано, чтобы не создавать дубли.

### FloodWait

Если Telegram отвечает FloodWait:

- Publication возвращается в PENDING;
- аккаунт получает FLOOD_WAIT;
- сохраняется время, до которого надо ждать;
- эта пауза не считается полноценной неудачной попыткой;
- после окончания ограничения планировщик сможет продолжить.

## Расписания

Путь: **Автоматизация → Расписания**.

Расписание — это правило генерации допустимых будущих времён. Уже созданный пост использует его через **Ближайший свободный слот** или Autopilot.

Окна задаются в локальном времени этого timezone.

**Дни недели**  
Отметьте дни публикации.

**Постов в день**  
Сколько слотов надо сформировать.

**Мин. интервал (минуты)**  
Минимальное расстояние между слотами.

**Макс. постов в день**  
Жёсткий верхний предел.

**Окна публикации**  
Например:

- 11:00–13:00
- 16:00–18:00
- 20:00–22:00

**Случайное время**  
Если включено, пост внутри своего сегмента окна получает детерминированное псевдослучайное время. Повторный расчёт одного и того же дня не должен хаотично менять слоты.

Если выключено — используются начала рассчитанных сегментов.

**Категории**  
Список категорий расписания.

**Исключённые даты**  
Формат YYYY-MM-DD. Например, 2026-12-31.

**Если публикация пропущена**  
Misfire policy.

### Как распределяются 3 поста по трём окнам

При трёх постах и трёх окнах каждый попадает в своё окно.

Если постов больше окон, они распределяются round-robin; окно делится на сегменты.

### Ограничения окон

- окна не должны перекрываться;
- одно окно не должно пересекать полночь;
- если нужен диапазон через полночь, разделите его на два окна.

### Пауза

Переключатель расписания останавливает выдачу новых слотов.

Удаление/пауза расписания не переписывает время уже запланированных постов. В UI при удалении прямо указано, что существующие scheduled posts сохраняют время.

### Preview

Нажмите **Показать слоты**, чтобы увидеть, какие времена система рассчитает до сохранения/использования.

### Misfire policy

Misfire — ситуация, когда время поста прошло, например пока планировщик был недоступен.

Есть grace-период из общих настроек. Небольшое опоздание внутри grace публикуется обычным образом.

Если пост просрочен сильнее grace:

**Пропустить (SKIP)**  
Пост снимается с конкретного времени и возвращается в **Подтверждён**. Он не публикуется автоматически.

**Опубликовать сразу (PUBLISH_IMMEDIATELY)**  
Просроченный пост остаётся due и будет продвинут на публикацию при восстановлении планировщика.

**Перенести на следующий свободный слот (RESCHEDULE_NEXT_SLOT)**  
ChannelOS ищет следующий свободный слот расписания. Если подходящего расписания/слота нет, использует безопасный fallback с разнесением, а не выпускает все просроченные посты одновременно.

Для каждого расписания можно выбрать свою политику или оставить политику рабочего пространства.

> **Совет:** для большинства редакционных сетей безопасный default — **Перенести на следующий свободный слот**.

## База знаний

### Зачем

Knowledge — не «обучение модели навсегда». Это структурированный актуальный контекст, который ChannelOS может добавлять в конкретный AI-запрос.

При удалении базы её документы не уничтожаются автоматически: интерфейс предупреждает, что они останутся доступны без базы.

**Факт (FACT)**

**Контакт (CONTACT)**  
Username, email, контактная информация.

**Хороший пример стиля (STYLE_EXAMPLE_GOOD)**  
Эталон того, как надо писать.

**Плохой пример стиля (STYLE_EXAMPLE_BAD)**  
Пример того, чего избегать.

**Архивный пост (HISTORICAL_POST)**  
Прошлый контент для контекста/стиля.

**Правило (RULE)**  
Явная инструкция.

**Запрещённое утверждение (PROHIBITED_CLAIM)**  
То, что AI не должен заявлять.

**Ссылка (LINK)**  
Нужный URL и его смысл.

После истечения устаревший факт не должен попадать в AI-контекст. Это полезно для временных акций, цен, контактов и условий.

## Автопилот

Путь: **Автоматизация → Автопилот**.

Autopilot в v0.3.0 реально реализован, но Web UI намеренно показывает не все внутренние параметры.

### Режимы

**Вручную (MANUAL)**  
Autopilot ничего не генерирует автоматически.

**С подтверждением (APPROVAL)**  
Планировщик может создать AI-пост, но результат останавливается в очереди подтверждения.

**Автопилот (AUTOPILOT)**  
Система может сгенерировать, подтвердить и поставить в следующий слот.

> **Совет:** начинайте с **С подтверждением**.

### Настройки, доступные в Web UI

**Куда публиковать**  
Channel Set.

**Расписание**  
Schedule или «Без расписания».

**Постов в день**  
От 1 до 50 на уровне UI.

**Дневной бюджет, ₽**

**Месячный бюджет, ₽**

**Макс. стоимость поста, ₽**

**Генерировать изображения**  
Доступно только если image provider сообщает AVAILABLE.

### Что происходит при AUTOPILOT

Планировщик раз в день создаёт AUTOPILOT_PLAN, если режим не MANUAL.

Для каждой планируемой единицы:

1. проверяется AI-бюджет;
2. выбирается категория;
3. генерируется Content Item;
4. если нужен review или дубликат выше блокирующего порога — пост идёт в Approval;
5. если категория news требует source, а source нет — пост идёт в Approval;
6. в режиме APPROVAL любой сгенерированный пост идёт в Approval;
7. в AUTOPILOT безопасный пост автоматически проходит submit/approve;
8. при наличии расписания выбирается следующий slot.

Если расписание не выбрано, auto-approved пост может остаться APPROVED, а не отправиться «прямо сейчас».

### Категории / content mix

В модели есть default mix:

- 40% educational;
- 25% news;
- 20% expert;
- 15% recruiting.

Но **в текущем Autopilot Web UI этот mix не редактируется**.

Так же UI не показывает отдельные поля duplicate thresholds, require_sources_for_news или max image regenerations, хотя backend использует их defaults.

### Бюджет

Autopilot проверяет бюджет **до нового AI-вызова**.

Если бюджет закончился:

- новые AI-генерации останавливаются;
- уже одобренные Telegram-публикации не отменяются.

Это важное разделение: AI-бюджет не является выключателем Telegram-доставки.

### Как быстро остановить автоматизацию

Вариант 1:

**Автопилот → Режим → Вручную → Сохранить.**

Вариант 2:

**⌘K / Ctrl+K → Приостановить автопилот.**

Если нужно остановить выдачу новых временных слотов конкретного Schedule, выключите его переключателем на странице **Расписания**.

## Задачи

Путь: **Автоматизация → Задачи**.

Jobs — главный технический экран, который всё ещё предназначен и для конечного пользователя при troubleshooting.

### Типы задач

В текущем UI доступны/могут встречаться:

- Генерация поста;
- Правка текста;
- Генерация изображения;
- Публикация в Telegram;
- Повтор публикации;
- Импорт каналов;
- Обновление метрик;
- Планирование автопилота;
- Загрузка источника.

Старые данные могут содержать legacy-имя старой AI rewrite job, но новые фильтры используют актуальные типы.

### Статусы

**В очереди (QUEUED)**  
Ожидает воркера.

**Выполняется (RUNNING)**  
Воркер взял задачу.

**Повтор (RETRYING)**  
Система ждёт следующую автоматическую попытку.

**Выполнено (SUCCESS)**  
Успех.

**Ошибка (FAILED)**  
Нужна проверка.

**Отменено (CANCELLED)**  
Задача отменена.

### Поиск и фильтры

Есть:

- строка поиска;
- фильтр статуса;
- фильтр типа.

Список обновляется автоматически.

### Подробности задачи

Открыв Job, вы увидите:

- human-readable summary;
- номер попытки / максимум;
- duration;
- progress;
- queued_at;
- started_at;
- worker;
- next retry;
- понятную ошибку;
- техническое сообщение;
- metadata;
- историю попыток.

### Retry

Кнопка появляется у FAILED, если задача разрешает повтор.

Для **DELIVERY_UNKNOWN** Retry специально заблокирован. Сначала решите неопределённую Telegram-доставку в Content Studio.

### Cancel

Доступен для QUEUED и RETRYING.

### Когда Retry лучше не нажимать

- если Telegram ещё в FloodWait;
- если delivery unknown;
- если ошибка — no permission, пока вы не исправили права;
- если AUTH_REQUIRED, пока не переподключили аккаунт;
- если AI budget exceeded, пока не изменился период/лимит;
- если provider unavailable, пока сервис не восстановлен.

### Идемпотентность простыми словами

ChannelOS старается не делать одну Telegram-отправку дважды. Publication имеет собственный ключ и атомарно «захватывается» воркером. Поэтому аварийное повторение задачи не означает автоматический дубль успешного поста.

### Input Tokens

Токены контекста, который был отправлен модели: инструкция, Knowledge, Tone, недавние темы и т. п.

### Output Tokens

Токены, которые модель вернула.

Пользователю не нужно считать токены вручную: важен итог в рублях и лимиты.

### Верхние показатели

**Сегодня**

**7 дней**

**Месяц**

**Прогноз на конец месяца**

### Прогноз

Backend берёт расход с начала месяца, считает средний темп по прошедшим дням и умножает его на количество дней месяца.

Пример:

- месячный бюджет: 1500 ₽;
- использовано: 430 ₽;
- прогноз: 1180 ₽.

Это означает: при текущем среднем темпе система ожидает закончить месяц ниже бюджета. Если темп резко изменится, прогноз также изменится.

### Бюджетная шкала

Показывает:

- потрачено;
- лимит;
- процент;
- warning color после порога;
- danger после 100%.

### Токены за месяц

Отдельно показываются суммы input/output tokens.

## Бюджет

Путь: **Настройки → Бюджет**.

### Дневной бюджет

Лимит AI-расхода за день.

### Месячный бюджет

Лимит за календарный месяц.

### Макс. стоимость поста

Защитный порог оценки одного AI-действия/поста.

### Порог предупреждения, %

По умолчанию 80.

При пересечении warning threshold создаётся уведомление бюджета. При достижении лимита — exceeded.

### Что происходит на 80%

При default warning 80% система создаёт предупреждение для текущего дневного/месячного периода. Оно дедуплицируется, чтобы не спамить одинаковым событием постоянно.

### Что происходит на 100%

Новые AI-операции, которые превышают лимит, блокируются.

Уже созданные одобренные Telegram-публикации продолжают выполняться.

### Безопасный стартовый preset

Текущие defaults backend:

- Дневной: **50 ₽**;
- Месячный: **1500 ₽**;
- Максимум на пост: **15 ₽**;
- Предупреждение: **80%**.

Для нового пользователя это разумная стартовая защита. Меняйте значения под реальный объём только после нескольких дней наблюдения.

## Роли и права

Роли:

- Владелец (OWNER);
- Администратор (ADMIN);
- Редактор (EDITOR);
- Согласующий (APPROVER);
- Наблюдатель (VIEWER).

Права имеют иерархию по уровню, поэтому более высокая роль проходит проверки более низкого уровня.

### Наблюдатель

Чтение доступных данных без прав редактора.

### Согласующий

Минимальная роль для approve/reject/publish/schedule workflow.

### Редактор

Может создавать и изменять контент и имеет более высокий ранг, чем Approver, поэтому также проходит approval-проверки.

### Администратор

Может управлять Telegram и настройками.

### Владелец

Имеет максимальный уровень и управляет участниками/ролями.

> **Важно:** даже если какая-то кнопка случайно видна в frontend, окончательная проверка роли выполняется backend. UI-гейтинг не является механизмом безопасности.

## Готовые сценарии работы

### Сценарий 1. Один пост → один канал

1. Создайте Channel Set из одного канала.
2. Создайте пост.
3. Выберите этот Set.
4. Отправьте на подтверждение.
5. Подтвердите.
6. Publish Now или Schedule.
7. Проверьте Publication.

### Сценарий 2. Один пост → 10 каналов

1. Создайте Talos Network из 10 каналов.
2. Выберите EXACT либо режим CTA.
3. Сгенерируйте один Content Item.
4. Проверьте текст.
5. Подтвердите.
6. Запустите публикацию.
7. Следите за десятью независимыми Publications.

AI не обязан генерировать основной текст десять раз.

### Сценарий 3. Два поста в день по расписанию

1. Откройте **Расписания**.
2. Создайте Schedule.
3. Выберите дни.
4. Поставьте **2 поста в день**.
5. Создайте два/несколько окон, например 12:00–14:00 и 19:00–21:00.
6. Установите min interval.
7. Сохраните.
8. Для подтверждённого поста выберите Schedule и **Ближайший свободный слот**.

### Сценарий 4. AI сделал пост → ручное подтверждение

1. Generate with AI.
2. Дождитесь DRAFT.
3. Отредактируйте.
4. Submit.
5. Перейдите в Approval.
6. Approve.
7. Schedule/Publish.

Это рекомендуемый старт.

### Сценарий 5. Ошибка в 2 из 10 каналов

1. Откройте Content Studio.
2. Найдите блок рассылки.
3. Убедитесь, что 8 SUCCESS.
4. Изучите две FAILED.
5. Исправьте причину.
6. Нажмите Retry Failed.
7. Проверьте, что повторились только две.

### Сценарий 6. Telegram account disconnected

1. Откройте Аккаунты.
2. Если DISCONNECTED/AUTH_REQUIRED — используйте **Добавить аккаунт**.
3. Войдите тем же Telegram-пользователем.
4. Обновите каналы.
5. Проверьте health.

### Сценарий 7. FloodWait

1. Не удаляйте аккаунт.
2. Посмотрите flood_wait_until.
3. Дождитесь времени.
4. Проверьте Jobs.
5. Планировщик продолжит PENDING-публикации после окончания wait.

### Сценарий 8. Заканчивается месячный AI-бюджет

1. Откройте Расходы.
2. Посмотрите Month и Forecast.
3. Откройте Настройки → Бюджет.
4. Решите: уменьшить генерации или изменить лимит.
5. Помните: одобренные Telegram-публикации не отменятся из-за AI limit.

### Сценарий 9. Нужно переписать AI-текст

1. Откройте Content Studio.
2. Сохраните ручные изменения.
3. Выберите **Переписать**, **Улучшить**, **Сократить** и т. п.
4. Дождитесь Job.
5. Сравните новую ревизию.
6. При необходимости Restore старой.

### Сценарий 10. Перенести публикацию на завтра

1. Откройте Календарь.
2. Найдите SCHEDULED.
3. Перетащите карточку на завтра или нажмите **Изменить время**.
4. Проверьте новое время и timezone.

## Рекомендуемый workflow для нового пользователя

1. Настройте язык и timezone рабочего пространства.
2. Подключите один Telegram-аккаунт.
3. Обновите каналы.
4. Исправьте NO_POST_PERMISSION.
5. Создайте один небольшой Channel Set.
6. Настройте workspace CTA.
7. Добавьте channel CTA overrides, если нужны.
8. Создайте Knowledge Base с актуальными контактами/правилами.
9. Создайте Tone Profile.
10. Установите AI-бюджет.
11. Сделайте 3–5 постов вручную/через AI.
12. Всегда используйте Approval.
13. Проверьте публикации, Jobs, расходы и метрики.
14. Создайте Schedule.
15. Переведите Autopilot из MANUAL в APPROVAL.
16. Несколько дней проверяйте результат.
17. Только после этого рассмотрите AUTOPILOT.

> **Совет:** автоматизация должна быть последним слоем поверх уже стабильных Telegram-аккаунтов, Channel Sets, Tone, Knowledge, бюджета и расписаний.

## Устранение неполадок

### Telegram требует повторный вход

**Признак:** Нужен повторный вход / AUTH_REQUIRED.

**Причина:** сохранённая Telegram-сессия больше недействительна.

**Что делать:**

1. Аккаунты → Добавить аккаунт.
2. Введите тот же номер.
3. Пройдите code/2FA.
4. Обновите каналы.
5. Повторите только FAILED публикации.

### Нет каналов после подключения

1. Подождите автоматический импорт.
2. Аккаунты → Обновить каналы.
3. Задачи → найдите импорт.
4. Проверьте, действительно ли Telegram-пользователь администратор канала.
5. Если AUTH_REQUIRED — войдите снова.

### Нет прав на публикацию

**NO_POST_PERMISSION / NO_PERMISSION**

ChannelOS видит канал, но подключённый аккаунт не имеет права отправлять посты.

Исправьте права в Telegram, затем **Обновить каналы**.

Retry до исправления прав бессмысленен.

### FLOOD_WAIT

Это rate limit Telegram.

ChannelOS:

- отмечает аккаунт FLOOD_WAIT;
- запоминает время;
- возвращает Publication в PENDING;
- не считает это полноценной попыткой;
- возобновит работу после wait.

Обычно ничего вручную делать не нужно.

### Пост завис в Запланирован

Проверьте:

1. время действительно уже прошло?
2. timezone;
3. Обзор → Планировщик;
4. Redis;
5. Задачи;
6. уведомления misfire.

Если планировщик был offline, после восстановления применится grace и выбранная misfire policy.

### Пост FAILED

Откройте:

1. Content Studio → публикации;
2. Job;
3. error code;
4. Notifications.

Дальше действуйте по причине. Не нажимайте Retry механически.

### PARTIALLY_PUBLISHED

Это означает: хотя бы один канал SUCCESS и хотя бы один FAILED.

Исправьте конкретные ошибки и нажмите Retry Failed. Успешные не повторятся.

### Доставка не подтверждена

**DELIVERY_UNKNOWN**

1. Откройте реальный Telegram.
2. Проверьте канал.
3. Если пост есть — Mark Published.
4. Если нет — Mark Failed.
5. Только после Mark Failed разрешайте Retry.

### AI provider unavailable

Проверьте:

- Обзор → Состояние системы/AI;
- Настройки → AI;
- Job;
- уведомление AI failed.

Если серверная конфигурация неверна, обычный пользователь не исправит API key через Web UI — нужен администратор сервера.

### Image provider unavailable

В production v0.3.0 реальный image provider через Timeweb Agent недоступен.

Это ожидаемое ограничение текущей версии. Используйте Upload/Gallery.

### Budget exceeded

Откройте:

- Расходы;
- Настройки → Бюджет.

Дождитесь нового дня/месяца либо осознанно измените лимит. Telegram-публикации уже одобренного контента продолжаются.

### Worker offline

Обзор покажет **Воркер — Недоступно**.

Симптомы:

- Jobs остаются QUEUED;
- AI не завершается;
- публикации не исполняются.

Это серверная проблема. Передайте администратору; не создавайте десятки повторных задач.

### Scheduler offline

Симптомы:

- scheduled time проходит;
- периодические источники/метрики/Autopilot не запускаются.

После восстановления система обработает misfire по политике.

### Redis offline

Могут пострадать:

- очереди/диспетчеризация;
- Telegram login flow;
- распределённые блокировки;
- realtime/служебная координация.

Это серверная проблема.

### Не загружается изображение

Проверьте:

- формат PNG/JPEG/WebP/GIF;
- размер;
- состояние S3 на Обзоре;
- ошибку MEDIA_UNSUPPORTED / UNSUPPORTED_MEDIA_TYPE.

### Язык интерфейса не сохраняется

1. Настройки → Общие → Язык.
2. Убедитесь, что вы вошли в аккаунт.
3. Обновите страницу.
4. Если не сохранилось — проверьте ошибку API/Network.

v0.3.0 сохраняет явный выбор в аккаунт; он должен переживать reload.

### Пишет «данные изменились»

**CONTENT_EDIT_CONFLICT / CONFLICT**

Кто-то изменил объект параллельно. Обновите страницу, перечитайте актуальную версию и повторите правку. Не перезаписывайте вслепую.

### Нельзя редактировать пост

**CONTENT_NOT_EDITABLE / NOT_EDITABLE**

Статус уже не допускает изменение, например публикация идёт/завершена. Для опубликованного сообщения используйте следующий новый Content Item; ChannelOS не редактирует отправленное сообщение задним числом через этот workflow.

### Нет свободных слотов

**SCHEDULE_NO_FREE_SLOTS**

Проверьте:

- schedule paused?
- есть дни недели?
- есть окна?
- exclude_dates;
- posts/day и max/day;
- min interval;
- target.

Backend ищет вперёд до 120 дней.

### Время уже прошло

**SCHEDULE_TIME_IN_PAST**

Выберите будущее время. Небольшая техническая погрешность допускается, но намеренно планировать в прошлое нельзя.

### Источник не загружается

Проверьте:

- URL;
- минимальный interval;
- Telegram account для Telegram source;
- last_error;
- SOURCE_FETCH Job.

Некоторые URL блокируются защитой **SOURCE_URL_BLOCKED**.

## Безопасность

### Код Telegram и 2FA

Не сообщайте их другим людям.

Текущий login flow использует код/пароль для одного вызова и не сохраняет эти значения. Временная сессия хранится ограниченное время и шифруется; финальная Telegram-сессия также хранится зашифрованно.

### API keys

Не публикуйте ключи AI, Telegram API hash, storage credentials или содержимое env.

Web Settings специально показывает часть серверной конфигурации как «настроено», а не раскрывает секрет целиком.

### Сессии Web

Периодически открывайте **Настройки → Безопасность**. Если видите чужой сеанс, используйте **Завершить другие сеансы** и смените пароль по установленной у вас процедуре.

### Autopilot

Никогда не начинайте с полного AUTOPILOT на всей сети.

Безопасный старт:

**MANUAL → APPROVAL → AUTOPILOT.**

### Budget

Всегда задавайте дневной и месячный лимит. Один monthly budget без контроля дневного всплеска хуже защищает от неожиданного расхода.

## Что не стоит делать

- Не нажимать Retry много раз подряд.
- Не повторять успешные Publications вручную.
- Не повторять DELIVERY_UNKNOWN до ручной проверки Telegram.
- Не удалять Telegram-аккаунт только из-за FloodWait.
- Не включать полный Autopilot сразу на всех каналах.
- Не повышать AI-бюджет, не проверив страницу Расходы.
- Не удалять Knowledge, не понимая, какой AI-контекст на него опирается.
- Не менять timezone перед запланированными публикациями без проверки Calendar.
- Не создавать перекрывающиеся Schedule windows.
- Не ожидать, что смена языка UI переведёт контент.
- Не считать Idea опубликованным постом.
- Не считать Source Fetch генерацией поста.
- Не ожидать, что отключение уведомления устранит саму ошибку.
- Не использовать ADAPTED как будто он доступен в UI v0.3.0.
- Не рассчитывать на реальную AI-генерацию изображений в текущем production.

## Глоссарий

**Workspace / Рабочее пространство** — контейнер команды, данных и настроек.

**Telegram Account** — подключённая Telegram-сессия пользователя.

**Channel / Канал** — Telegram-канал в рабочем пространстве.

**Channel Set / Набор каналов** — группа каналов-целей.

**Content Item / Пост** — единица контента до и после публикации.

**Publication / Публикация** — доставка Content Item в один канал.

**Distribution Batch / Рассылка** — все Publications одного поста для одного Channel Set.

**AI Generation** — создание/изменение контента AI-провайдером.

**Approval / Подтверждение** — ручная проверка перед доставкой.

**Schedule / Расписание** — правило вычисления будущих времён.

**Series / Серия** — набор последовательных тематических постов.

**Source / Источник** — место, откуда загружаются материалы.

**Idea / Идея** — кандидат из Source, ещё не пост.

**Knowledge / База знаний** — факты, правила и примеры для AI-контекста.

**Tone of Voice / Тон и стиль** — профиль редакционного голоса.

**Job / Задача** — фоновая операция.

**FloodWait** — требование Telegram подождать перед следующими запросами.

**CTA** — призыв/контактный блок, который можно подставлять по ключу.

**Idempotency / Идемпотентность** — защита от повторного выполнения уже выполненной доставки.

**Budget / Бюджет** — лимиты AI-расходов.

**Autopilot / Автопилот** — планировщик автоматической генерации и, в полном режиме, подтверждения/расписания.

**Misfire** — публикация, время которой прошло, пока планировщик не смог вовремя её обработать.

**Delivery Unknown** — состояние, когда нельзя достоверно понять, дошло ли сообщение до Telegram; нужен человек.

## FAQ

### 1. Можно ли подключить несколько Telegram-аккаунтов?

Да. Страница **Аккаунты** рассчитана на несколько подключений.

### 2. Можно ли один пост отправить сразу в 10 каналов?

Да. Создайте Channel Set из десяти каналов и выберите его у одного Content Item.

### 3. AI будет десять раз списывать деньги за основной текст?

При обычных режимах EXACT / CTA_PER_CHANNEL / CONTACT_PER_CHANNEL основной Content Item не генерируется повторно на каждый канал. Рассылка переиспользует текст.

### 4. Что будет, если один канал недоступен?

Его Publication может завершиться ошибкой, в то время как остальные каналы продолжат независимо.

### 5. Можно ли повторить только неудачные каналы?

Да. **Retry Failed** повторяет только FAILED.

### 6. Можно ли изменить пост перед публикацией?

Да, пока статус допускает редактирование. После ручных правок сохраните изменения и при необходимости снова пройдите Approval.

### 7. Можно ли отменить запланированный пост?

В Content Studio для SCHEDULED есть действие снять с расписания. Статус возвращается к APPROVED.

### 8. Что такое Approval?

Ручной контроль между черновиком и публикацией.

### 9. Можно ли работать без AI?

Да. Создавайте ручные черновики.

### 10. Можно ли загрузить свою картинку?

Да. Галерея принимает PNG/JPEG/WebP/GIF.

### 11. Работает ли AI-генерация изображений?

В fake/dev режиме может работать. В текущем production с реальным Timeweb Agent image provider недоступен, поэтому кнопка отключена.

### 12. Что делать при FloodWait?

Подождать. Не удалять аккаунт и не спамить Retry.

### 13. Почему канал не публикует?

Чаще всего: нет прав, Telegram account offline/AUTH_REQUIRED, FloodWait, unavailable или серверный worker.

### 14. Где смотреть расходы?

**Аналитика → Расходы**.

### 15. Как ограничить расход?

**Настройки → Бюджет**: daily, monthly, max per post, warning %.

### 16. Могу ли я изменить язык?

Да: login EN/RU, меню пользователя или Настройки → Общие.

### 17. Переведётся ли мой пост при смене языка интерфейса?

Нет.

### 18. Что происходит после restart сервера?

Состояние Jobs/Publications хранится в БД, scheduler восстанавливает потерянные очереди и обрабатывает overdue posts по misfire policy. Для Telegram mid-send используется безопасный Delivery Unknown, а не слепой resend.

### 19. Что делать, если воркер упал посреди задачи?

Система умеет обнаружить stale RUNNING. Обычная задача переходит в retry/failed по правилам. Для Telegram mid-send безопасность важнее автоматического повтора.

### 20. Зачем нужен Channel Set, если у меня один канал?

Даже один канал можно держать в отдельном Set — тогда весь контентный workflow остаётся одинаковым и позже легко добавить каналы.

### 21. Можно ли настроить отдельный CTA для каждого канала?

Да, через CTA overrides канала и соответствующий режим Channel Set.

### 22. Можно ли задать отдельный Tone для канала?

Да.

### 23. Какой Tone победит, если профили есть в нескольких местах?

Явный Content Studio → Series → Channel → Workspace.

### 24. Что происходит при Restore старой версии?

Старая версия становится текущим содержимым, но история сохраняется и добавляется новая restore revision. APPROVED возвращается в Pending Approval.

### 25. Можно ли перенести пост drag & drop?

Да, если он SCHEDULED.

### 26. Можно ли делать окна 23:00–01:00?

Нет одним окном. Разбейте диапазон вокруг полуночи на два окна.

### 27. Что такое «Случайное время» в Schedule?

Время выбирается внутри рассчитанного сегмента окна. Расчёт детерминирован, поэтому один день не должен прыгать при каждом preview.

### 28. Что произойдёт, если AI-бюджет закончился, а пост уже одобрен?

AI-генерации остановятся, но одобренная Telegram-публикация не блокируется AI-бюджетом.

### 29. Что делает режим Autopilot «С подтверждением»?

Создаёт AI-контент, но останавливает его в Approval, пока человек не подтвердит.

### 30. Может ли полный Autopilot всё равно отправить пост в Approval?

Да. Например, если requires_review, высокий duplicate score или news без обязательного источника.

### 31. Можно ли менять content mix Autopilot из Web UI?

В v0.3.0 нет. Default mix есть в backend, но отдельные поля mix на странице не представлены.

### 32. Что такое Idea и почему она не появилась в Posts?

Idea — материал-кандидат. Нажмите **Сгенерировать пост**, чтобы создать Content Item.

### 33. Source сам публикует найденный материал?

Нет. Source Fetch создаёт Ideas.

### 34. Как часто обновляются Telegram-метрики?

Планировщик создаёт refresh job примерно раз в час для пространств с недавними успешными публикациями.

### 35. Где посмотреть, кто подтвердил или перенёс пост?

В **Журнале аудита**.

### 36. Можно ли пользователю в Web UI изменить API keys?

Нет. Telegram/AI/Storage вкладки в основном показывают состояние серверной конфигурации.

### 37. Что делать, если кнопка недоступна из-за роли?

Обратитесь к владельцу/администратору. Backend всё равно проверяет права, даже если UI что-то отобразил.

### 38. Можно ли удалить опубликованный пост из истории ChannelOS?

Backend не позволяет обычное delete для PUBLISHED/PARTIALLY_PUBLISHED. Используйте Archive. Это также не является удалением сообщения из Telegram.

### 39. Что произойдёт, если Channel Set пуст?

Планирование/публикация остановится с ошибкой **В наборе нет каналов**.

### 40. Когда использовать Publish Now, а когда Schedule?

Publish Now — если публикация должна стартовать сейчас. Schedule — когда важны редакционный график, timezone, интервалы и предсказуемая очередь.

## Ограничения текущей версии

Чтобы не создавать ложных ожиданий:

1. **ADAPTED** есть в backend enum, но не предлагается редактором Channel Set.
2. Реальный **Timeweb image provider** в production v0.3.0 недоступен; свои изображения загружать можно.
3. Отдельной кнопки **Reconnect** у Telegram Account нет; повторная авторизация выполняется через Add Account тем же пользователем.
4. Approval — это фильтрованный список PENDING_APPROVAL, который открывает общий Content Studio, а не отдельная специализированная карточка.
5. В Settings нет вкладки Appearance.
6. В Channel settings нет отдельных UI-полей schedule/limits/account reassignment.
7. На Performance нет отдельных growth/engagement/cross-channel detail экранов.
8. Category mix и некоторые защитные thresholds Autopilot не редактируются через текущий Web UI.
9. Source editor предлагает RSS, URL, manual и Telegram; отдельный website вариант, несмотря на наличие локализованной подписи, не предлагается.
10. Реальные AI/Telegram операции зависят от серверной конфигурации и внешних провайдеров.

## Короткая памятка

- Один пост на много каналов → **Channel Set**, а не копии поста.
- Перед публикацией новичку → **Approval**.
- 8 success / 2 failed → **Retry Failed**, не Publish Again.
- Delivery Unknown → сначала проверить Telegram.
- FloodWait → ждать.
- AI budget закончился → генерации остановятся, одобренная доставка продолжится.
- Autopilot быстро остановить → **⌘K/Ctrl+K → Приостановить автопилот**.
- Ошибка непонятна → **Задачи → открыть Job → попытки/код/технические детали**.
- Кто что сделал → **Журнал аудита**.
- Сколько потрачено → **Расходы**.
